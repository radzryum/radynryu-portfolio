  1. ACCOUNTS, ROLES, AND LOGGING IN
================================================================================
  - Open the login page and click "Log In" (also reachable from the public
    landing page header and mobile menu).
  - The login form has two fields:
      * "Email address or Account Number/ID" — you may type either your
        account email (for example you@example.com) or your ID, such as a
        student ID (CMPS-XXXX-XXX format) or an employee ID (CMPS-EMP-...).
        ID login works regardless of uppercase or lowercase typing.
      * "Password".
  - Optional "Remember me" checkbox (keeps you signed in on this device).
  - Click "Log In". While signing in the button shows "Signing in...".
  - After login you are sent to your home page automatically based on role:
      * Client (parent/caregiver) ......... Client Home & Progress
      * Psychometrician ................... Task List
      * Psychologist ...................... Tasks dashboard
      * Administrator / Super Admin ....... Dashboard Overview
  - If login fails you will see "Invalid email or password."
  - Need an account? Accounts are created by the clinic. The login page
    states: "Need an account? Please contact the ClearMind admin office
    to be registered." There is no public self-registration for staff;
    client self-signup always creates a client account only.

  ROLES IN BRIEF
  - Client ............ Parent/caregiver. Views the child's progress,
                        writes the Daily Journal, answers assessments and
                        consent forms, views appointments and announcements,
                        requests official document copies for clinic pick-up.
  - Psychometrician ... Handles assigned students only. Administers
                        assessments, writes Daily Activity Reports, monthly
                        reports, IEPs, behavioral reports, and records
                        attendance for assigned students.
  - Psychologist ...... Reviews and approves the psychometrician's work
                        (submissions, reports, IEPs, daily activity, monthly
                        reports), manages the student roster progress, marks
                        sessions done.
  - Administrator ..... Manages students, employees, compliance, the master
                        schedule, attendance records (all students),
                        announcements, website content, and clinical records.
  - Super Admin ....... Everything an Administrator can do, PLUS full
                        control over administrator accounts (create, view,
                        edit, delete admins) and a cross-branch "All
                        branches" view. See Section 8.

  2. PASSWORD RECOVERY (FORGOT PASSWORD)
================================================================================
  1. On the login page click "Forgot password?".
  2. STEP 1 — Enter your registered email address, then click
     "Send Verification Code". (Button shows "Sending code..." while busy.)
     Click "Back to Log In" to cancel and return.
  3. STEP 2 — "Check your email": a 6-digit verification code is sent to
     that address and expires in 10 minutes. Type the code into the six
     boxes (digits only; typing auto-advances, Backspace goes back, and
     you can paste all 6 digits at once). Click "Verify Code".
     Links: "Change Email" (go back to Step 1), "Resend Code" (sends a
     fresh code; note: a resent code replaces the previous one).
  4. STEP 3 — Type "New Password" and "Confirm Password", then click
     "Reset Password". Rules (shown in a red box if violated):
       * At least 8 characters
       * At least one uppercase letter
       * At least one number
       * Both entries must match
  5. A "Password Reset!" success modal appears. Click "Return to Log In"
     and sign in with the new password.
  IMPORTANT:
  - Use the EXACT email registered on your account (check your welcome
    email or ask the clinic). For security, the system always advances to
    the code screen even if the typed email has no account — in that case
    no email is ever sent. If no code arrives within a few minutes, check
    the spam folder and confirm the registered email with the clinic.

  3. COMMON SCREEN ELEMENTS (SIDEBAR, HEADER, NOTIFICATIONS, HELP)
================================================================================
  SIDEBAR (left, all logged-in users)
  - Top profile card: your photo (or initials icon), display name, role
    label, and ID pill (student ID for clients, employee ID for staff).
    Clicking the card opens your profile page.
  - STAFF WITH MORE THAN ONE ROLE: under your name you will see one
    badge per role you hold (for example Administrator + Psychologist).
    The badge of the role you are currently acting as is solid purple;
    the others are faded. Below the badges is a "Switch Role" pill
    button that opens the role picker — see Section 3.2.
  - Navigation list: one item per section (see role chapters below). The
    active page is highlighted. Some items show a count badge for unread
    items.
  - Bottom card: "CyMon / ClearMind Clinic" logo and a Help button.
  - On small screens the sidebar becomes a slide-in panel with a "Close
    menu" (X) button; navigation closes it automatically.
  - On desktop a collapse button can hide/show the sidebar (remembered).

  HEADER (top bar)
  - Left: menu button (mobile) or show/hide sidebar (desktop), then the
    page title.
  - Right: today's date, the BRANCH SWITCHER (staff working in 2+
    branches, and all Super Admins — see Section 3.1), a light/dark
    ThemeToggle switch, the Notifications bell, and a logout (exit)
    icon.
  - Logout icon asks "Sign out? / Are you sure ...?" — "Cancel" stays,
    "Log Out" signs you out and returns to the login page.

  NOTIFICATIONS BELL
  - Click the bell to open the last 10 notifications. Unread ones are
    marked "N NEW". Icons/colors vary by type (approvals, returns,
    reports, assessments).
  - "Mark all as read" clears the unread state.
  - Clicking a notification marks it read and jumps straight to the
    related page (for example an assessment, activity report, approval,
    or attendance page).
  - The header polls automatically (about every minute), and badges also
    refresh on navigation and workflow actions.
  - If empty: "You're all caught up — no notifications yet."

  HELP / ONBOARDING TOUR
  - The sidebar Help button ("Help & Support" / "?") opens a guided tour
    explaining each sidebar button and the workspace inside each page.
  - First-time users see the tour automatically; completing it saves so
    it does not show again (per role).

  --------------------------------------------------------------------------
  3.1 BRANCH SWITCHING (acting branch)
  --------------------------------------------------------------------------
  - Staff accounts can be given access to more than one clinic branch
    (for example ClearMind Alabang and ClearMind Cabuyao) under a single
    email/login. The header BRANCH SWITCHER (building icon + branch
    name, between the date and the theme toggle) picks which branch you
    are acting in. Every list, directory, and schedule in the workspace
    then shows only that branch's data.
  - WHO SEES IT: the switcher is hidden when there is nothing to switch
    between. It appears only for (a) staff who can act in 2 or more
    branches, and (b) Super Admins, who always see it.
  - SUPER ADMIN — "All branches": the Super Admin's switcher has an
    extra "All branches" option (the default when nothing was picked).
    It shows a cross-branch view of every clinic at once. Picking a
    specific branch narrows everything to that branch; picking "All
    branches" again returns to the cross-branch view.
  - HOME BRANCH: your main branch is marked "Home branch" in the
    dropdown. Choosing it again simply returns you to your home scope.
  - SWITCHING OVERLAY: picking a branch plays a two-beat modal —
    "Switching to {branch} / Loading this branch's workspace..." and
    then "Now you are in {branch}". The workspace lists refetch behind
    the modal (no full-page reload), so you never see the old branch's
    data flash. You can dismiss the modal early; the switch still
    applies.
  - The dropdown header reads "Acting branch"; the current branch shows
    a "Current" tag. Your choice is remembered on this device (stored
    locally). If a branch is later revoked from your account, the saved
    choice is dropped automatically and you fall back to your home
    branch.
  - Regular admins are locked to their own branch server-side: even the
    Applications page branch filter and the Data Export downloads only
    ever return their own branch's records.

  --------------------------------------------------------------------------
  3.2 ROLE SWITCHING (multi-role staff)
  --------------------------------------------------------------------------
  - Some staff hold MORE THAN ONE role on a single account (a primary
    role plus extra roles — for example Administrator who is also a
    Psychologist). The sidebar profile card shows every held role as a
    badge (solid = the role you are acting as right now, faded = the
    others) plus a "Switch Role" pill button.
  - Clicking "Switch Role" opens a dropdown card listing each role
    ("Current" tag on the active one). Picking a role plays a two-beat
    modal — "Switching to {role} / Loading your workspace..." and then
    "Now you are in {role} / Workspace updated." — and then navigates
    you to that role's dashboard (e.g. /admin for Administrator,
    /psychologist for Psychologist, /psychometrician for
    Psychometrician and the legacy Speech/Occupational Therapist
    roles).
  - WHY IT MATTERS: the backend scopes every directory to the role you
    are acting as. Staying on the wrong role shows the wrong (often
    empty) lists. If you open a notification link and land on an empty
    directory, switch to the matching role first.
  - The URL always wins over the saved role: visiting /psychologist/*
    acts as psychologist, /psychometrician/* as psychometrician, and
    /admin/* as admin, regardless of the last role you picked. Your
    last explicit pick is remembered on this device for the next visit.
  - If a role is removed from your account (for example on a shared
    computer after an admin change), the stale saved role is cleared
    automatically so lists do not stay wrongly filtered.
  - Single-role users never see "Switch Role" — there is nothing to
    switch between.

  4. CLIENT GUIDE (PARENT/CAREGIVER PORTAL)
================================================================================
  Sidebar: Home & Progress | Daily Journal | Assessment Services |
  Announcements | Appointments | Consents & Waivers | Activity History.

  --------------------------------------------------------------------------
  4.1 HOME & PROGRESS (/client/home)
  --------------------------------------------------------------------------
  - Greeting header ("Good Day, <first name>!") with the summary:
    "Your care team, schedule, assessments, and daily progress in one place."
  - Stat cards: "Pending Assessments" (count; click to open Assessment
    Services) and "Turn in Daily Journal" (Locked / Submitted / Pending).
  - "Assigned Clinical Care Team": cards for your Psychologist and
    Psychometrician (photo/initials, role, PRC license or "N/A").
    If none assigned: "No assigned team."
  - "My Feelings This Week": 7-day mood dots (today is ringed; hover a
    dot to see the day). Default message "Tell us how you feel today!"
    If no journal yet, a "Log your feelings now" link opens Daily Journal.
  - "Next Appointment" (purple) and "Last Appointment" cards, or
    "No upcoming/past appointment."
  - "Recent Announcements" list with "View all announcements" link.
  - This page refreshes when you return to the tab and about every
    30 seconds. If loading fails, an error banner appears with
    "Reload the page to try again."

  --------------------------------------------------------------------------
  4.2 DAILY JOURNAL (/client/activity) — "Daily Journal"
  --------------------------------------------------------------------------
  - Intro: "Record daily observations and progress."
  - If the clinic has not enabled journaling for your child, a "Unable
    to Access Daily Journal" banner shows and everything is locked
    ("ask permission to your assigned Psychometrician"). While locked,
    submitting shows "Journal writing ... locked".
  - Form (left): "Journal Date" header with date picker (never in the
    future) and "Go to Today" button (appears when viewing another day).
    Fields:
      * "Observations & Daily Journal" notebook textarea — REQUIRED
        ("Please fill in your observations before submitting."). Locked
        placeholder reads "Journal writing is currently locked...".
      * "How was their general mood today?" — 5 choices:
        Very Bad, Sad, Okay, Good, Great (default Okay).
      * "Daily Metrics & Observations" dropdowns (all optional):
        Therapy task completion (all/some/none), Behavioral episodes
        (none/mild/significant), Sleep quality (well/restless/poor),
        Appetite (good/average/refused).
  - Buttons: "Submit Journal Entry" (new day) or "Update Journal Entry"
    (existing day) — both ask confirmation ("Confirm journal
    submission/update" → "Yes, submit/update journal"). "Delete Journal
    Entry" (only for a saved date) asks "Delete Journal Entry? / Are
    you sure...?" before deleting.
  - "Journal Archive & History" (right): "Search past logs..." box,
    status pill ("not yet started / completed — not yet submitted /
    submitted"), and the log list. Each entry has "View Entry" to load
    that date into the form. Empty: "No submissions yet." / "No matching
    logs found."
  - "Mood This Week" line chart ("Not enough data yet" if fewer than
    2 points).

  --------------------------------------------------------------------------
  4.3 ASSESSMENT SERVICES (/client/assessments)
  --------------------------------------------------------------------------
  Intro: "Request official completed assessment documents for clinic
  pick-up." This page has two jobs: (A) answer assessments assigned to
  your child, (B) request official copies of finished documents.
  - Status banners (top): "Pick-Up Appointment Scheduled & Approved"
    (visit date/time, total fee, "Payment Confirmed" / "Online Payment
    Pending" / "Payment Due at Clinic", optional clinic notice) or
    "Document Request Pending Clinic Review" (being reviewed).
  - "Completed Assessments" card grid ("Select documents to request for
    clinic pick-up."). Each card: status badge (Not Administered /
    Pending Approval / In Progress / Completed / Ready for Pick-Up /
    Released / Request Pending / Request Declined) and completion date
    ("Awaiting completion" vs "Completed on ...").
    Buttons per card: "Request Copy" toggles to "Selected for Request"
    (only for completed/approved/finalized documents with no active
    request; otherwise "Unavailable for request"), "View Pick-Up Slip"
    / "View Slip" / "View Receipt" for requests.
  - "Progress & Program Reports" (only if any): IEP, Monthly Assessment
    and Daily Activity Reports available for request.
  - "Document Request History": past requests and their statuses.
  - Sticky bottom bar (when 1+ selected): "N Document(s) Selected /
    Ready to request for clinic pick-up" with "Clear" and
    "Request Documents".
  - Request flow: "Request Documents" → "Request Confirmation / Are you
    sure you want to request N document(s)...? [Yes/No]" → "Choose
    Payment Method" ("Pay Onsite": cash/GCash/Maya/GoTyme/MariBank at
    the cashier; "Pay Online": secure PayMongo card/GCash/PayMaya/
    GrabPay) → "Confirm & Submit Request". If any selected document was
    already released before, "Reason for Requesting Copy" is REQUIRED.
  - "Pay Now Online" (only for scheduled requests set to online payment
    and unpaid) redirects to the PayMongo checkout page.
  - Pick-up slip modal: "Download Slip" saves the official PDF
    ("{student-id}-assessment-pick-up-slip.pdf"); "Close" dismisses.
  - Empty: "No assessment documents available yet." /
    "No document requests yet."

  ANSWERING AN ASSESSMENT (/client/assessments/:id)
  - Header "Assessment Services" with "Complete the assessment and
    submit it from this page." "Back to Assessments" returns to the list
    (the embedded form's close does the same). Answer all required items
    in the form and submit; a skeleton shows while loading and a red box
    shows any load error.

  --------------------------------------------------------------------------
  4.4 APPOINTMENTS (/client/appointments) — read-only schedule
  --------------------------------------------------------------------------
  - "My Appointments Schedule / Upcoming sessions and schedule details."
  - Top "Date:" picker jumps the calendar. Calendar panel: "Prev |
    MONTH YYYY + TODAY | Next", SUN..SAT header, and day cells showing
    event chips ("8:00 AM — Session Label" + practitioner). Session
    labels include MMSE/CAFAT/GARS Assessment, Initial Assessment,
    Follow-up Session, Therapy Session, Parent Consultation. Statuses:
    Upcoming / Completed / Cancelled / Missed.
  - Side panel "Schedule: MONTH day": timeline of time + status pill,
    title, "Practitioner: ...", location, and "Note:" box.
  - Buttons: "Prev"/"Next" month (resets to day 1), "TODAY" (jumps to
    today), clicking a day selects it. There are no booking or cancel
    buttons — to change a session, contact the clinic.
  - Empty: calendar icon + "No sessions scheduled / for this day".

  --------------------------------------------------------------------------
  4.5 CONSENTS & WAIVERS (/client/waivers)
  --------------------------------------------------------------------------
  - "Consents & Waivers / Required forms, waivers, and submission
    status." Panel: "Waivers & Consent Forms". Always two documents:
      * CMPS:SE-FO-01 — Student Admission Form (personal info, parents
        details, diagnosis, disability, enrollment program selection).
      * CMPS:SE-FO-02 — SPED Consent and Waiver (parent/caregiver consent
        for the Special Education Program).
  - Desktop table (Document Title | Form Code | Status | Actions) and
    mobile cards show the same rows. A violet "Clinic note: ..." box
    appears on forms the clinic returned for revision.
  - Buttons per row: "Answer Form" (purple, when not yet submitted/
    approved) opens the form; "View PDF" (outline, when submitted/
    approved) opens a read-only preview.
  - Statuses: Submitted & Answered (sky), Approved & Completed
    (emerald), Returned — Needs Revision (violet pulse), Pending
    Signature (amber), Signature Required (rose pulse), Overdue
    (rose pulse), Action Required (rose solid pulse).

  ANSWERING A FORM (/client/waivers/:id, :id = CMPS:SE-FO-01 or -FO-02)
  - "?view=true" opens read-only preview; otherwise the form is editable
    unless already submitted/approved (then everything is disabled).
  - "Back" returns to the list. A violet "Returned for Revision"
    banner ("Clinic note: ... / Please update... and re-submit.")
    appears when the clinic sent the form back.
  - FO-01 sections (read-only info blocks): Personal Information
    (names, birthdate, age, sex, nickname, addresses, citizenship,
    religion, 2x2 ID picture box), Parent Information (mother + father:
    name/occupation/mobile/email), Emergency Contact Information,
    Clinical Details (diagnosis, disability, allergies, enrollment
    type), Signatures (parent + clinic representative with
    profession/PRC No.).
  - FO-02: sticky "Acknowledgment status done/total" progress bar
    ("All sections have been read..." at 100%), provision cards each
    with "I have read, understood, and agree... Item N." checkbox (ALL
    required: "Please agree to all provisions..."), "Cymon's House
    Rules" list + acknowledgment checkbox, and the "Parent / Caregiver
    Acknowledgement Form" ("I, {parent}, ... parent/legal guardian of
    {child}...") with: Parent/Guardian Full Name (required), Parent
    Contact Number (09xx format, required), Date, Child/Student Full
    Name, and Parent/Guardian E-Signature pad (draw with mouse/stylus/
    touch; required: "Parent / guardian e-signature is required.").
    The representative side is read-only.
  - Footer: editable mode shows a hint + "Submit Form" (submits and
    returns to the list); read-only mode shows "Ready to export /
    Preview the generated database-backed PDF..." + "Preview Official
    PDF" (opens the official PDF modal with download; file is named
    "{student-id}-{form-code}.pdf").
  - Blank values show "—"; missing signatures show "No signature on
    record / No signature image submitted / Pending clinic
    representative signature".

  --------------------------------------------------------------------------
  4.6 ANNOUNCEMENTS (/client/announcements)
  --------------------------------------------------------------------------
  - "Announcements / Latest clinic updates, notices, and upcoming
    events." Header card: "N notice(s) available" + Previous/Next
    announcement chevrons on desktop.
  - Mobile: stacked post list; desktop: horizontal snap carousel. Each
    card: "ClearMind Clinic", date, Urgent/Event/Info badge, title,
    3-line preview, optional image, footer "Clinic announcement / Tap
    to read more". Clicking opens the detail modal (full body, calendar
    date, "ClearMind Clinic / Official clinic announcement", hero image
    or purple megaphone fallback). Modal closes via X, "Close", or
    backdrop click. Reading marks it read (badge clears).
  - Empty: "No active announcements right now. Check back soon!"
    Loading shows skeleton cards.

  --------------------------------------------------------------------------
  4.7 MY PROFILE (CLIENT) (/client/profile)
  --------------------------------------------------------------------------
  - "My Profile". Hero: photo/initials, full name, "Patient ID: ...",
    pills (IEP level, clinic, psychologist).
  - Notice: "To update your personal details, please contact the
    ClearMind clinic administration." (Clients cannot edit their own
    clinical/personal data.)
  - "Personal Information": full name, patient ID, birthdate, age,
    sex, nickname, birthplace, citizenship, religion, contact, present
    and permanent addresses.
  - "Clinical Information": chief complaint, working diagnosis,
    diagnosis, secondary diagnosis, allergies, IEP level, assigned
    psychologist/psychometrician, clinic, date enrolled, last
    assessment, next review. Blank fields show italic "Not specified".
  - "Guardian & Emergency Contact": mother/guardian and father/
    guardian (name/occupation/contact/email) + emergency contact
    (name/relationship/contact).
  - "Account Settings": account email + "Change" (opens) / "Close"
    password form: Current / New / Confirm New Password with
    Show/Hide per field, "Update Password" (rules: new password at
    least 6 characters; must match; asks "Confirm password update /
    Yes, update password"). Success: "Password updated."

  --------------------------------------------------------------------------
  4.8 ACTIVITY HISTORY (CLIENT) (/client/history)
  --------------------------------------------------------------------------
  - "Activity History": your own account log for the last 30 days —
    sign-ins (with device and approximate location) and actions you
    took. A search box filters by action or keyword. Read-only; there
    is nothing to approve or edit here.

  Activity History.
  IMPORTANT: a psychometrician only ever sees students ASSIGNED to them
  (their "treating psychometrician" caseload). Students assigned to

  First visit shows a guided tour; the Help button replays it.

  --------------------------------------------------------------------------
  5.1 TASK LIST (/psychometrician) — home page
  --------------------------------------------------------------------------
  - Greeting header. Three metric cards: "Sessions Today",
    "Pending Assessments" (count), "Reports to Draft" (count).
  - "Today's Queue" with two tabs: "Sessions" and "Documents"
    (assessments + draft reports), grouped by student with
    "N Documents Pending".
  - Buttons: per session "Mark as Done" (marks today's appointment
    complete); expand a student group (chevron); per document
    "Administer" (start an assigned template), "Continue Draft"
    (resume a draft report), or "Open" — each jumps to the right tool
    (assessments, IEP, daily activity, monthly report) with the student
    pre-selected.
  - "Quick Actions": Assessments, Draft Reports, Data Review,
    IEP Workspace shortcuts.
  - Status pills: draft/in_progress (amber), revise_requested
    ("revision needed", orange), assigned (blue).
  - Empty: "No sessions scheduled for today." /
    "No pending assessments."

  --------------------------------------------------------------------------
  5.2 STUDENTS (/psychometrician/roster) — assigned roster, view-only
  --------------------------------------------------------------------------
  - "Students": your assigned-student list with support level
    (HSN/MSN/LSN) and milestone progress per row. Search by name or
    support level. Read-only — roster progress and notes are updated
    by the psychologist (Section 6.2); opening a record shows its
    details plus the intake summary.
  - Empty: "No assigned students yet." / "No students match your
    search."

  --------------------------------------------------------------------------
  5.3 INTAKE INTERVIEW (/psychometrician/intake) — shared record
  --------------------------------------------------------------------------
  - The first assessment before treatment, co-filled with the
    psychologist on ONE shared record per student. Left: student picker.
    Right: the interview form (chief complaint, background, initial
    observations). Entries autosave and every field tracks who edited
    it and when (per-field edit history).
  - The psychologist-only roster-impression fields stay locked for
    psychometricians; fill in your own sections and the psychologist
    completes theirs on the same record (Section 6.3).

  --------------------------------------------------------------------------
  5.4 ASSESSMENT SERVICES (/psychometrician/assessments)
  --------------------------------------------------------------------------
  - "Select and administer... Submissions will be forwarded..." to the
    psychologist for review.
  - Left "Student Directory" (search; disabled while a form is open).
    A student can only be assessed when admission is complete AND the
    SPED consent (CMPS:SE-FO-02) is approved — otherwise buttons are
    disabled with tooltip "Admission and Consent ... must be approved
    first."
  - Right: student header + "Standardized Assessment Templates" table
    (Assessment Tool | Status | Actions) + "Behavioral Assessment
    Reports" ledger (Report Title | Last Updated | Status | Actions)
    with "Write Behavioral Assessment Report" button (only for your own
    assigned students with no report yet).
  - Buttons per template: "Answer Assessment" (not started),
    "Continue Assessment" (draft), "Answer (Revalidate)" + "View Form"
    (returned for revalidation), "View Form" (submitted/approved).
    "Back to Dashboard Tables"/"Back" exits form view (directory
    re-expands).
  - Inside a returned form, a red "Psychologist's Note" panel shows the
    reviewer's comment.
  - Statuses: Not Started (slate), Draft (slate), Pending Approval
    (sky), Revalidation Required (amber), Approved & Completed
    (emerald); behavioral reports: DRAFT (amber), SUBMITTED (sky),
    APPROVED (emerald), RETURNED FOR REVISION (orange).
  - The form view supports URL deep links (?patientId, templateId,

================================================================================
  8. SUPER ADMIN — WHAT IS DIFFERENT FROM ADMIN
================================================================================
  A super admin sees the exact same 12-item sidebar and pages as an
  administrator (Overview, Students, Applications, Employees,
  Compliance, Front Desk, Attendance, Clinical Records, Data Export,
  Content Manager, Announcement, Audit Trail). The differences are
  scope (branches) plus control over administrator accounts:

  - BRANCH SCOPE (Section 3.1): a Super Admin's header branch switcher
    always shows and defaults to "All branches" — a cross-branch view
    where every list, directory, and schedule spans all clinics.
    Picking one branch narrows the whole workspace to it. Regular
    admins are locked to their own branch and never see "All
    branches".
  - APPLICATIONS (Section 7.3): Super Admins get one QR/link card per
    branch, an "All Branches" filter over the inbox, and a branch pill
    on every row. Regular admins see only their own branch's card and
    rows.
  - DATA EXPORT (Section 7.9): Super Admins export ALL branches;
    regular admins export only their own branch.
  - EMPLOYEE MANAGEMENT (/admin/employees):
    * REGISTRATION: only a super admin sees/offers the
      "Administrator" and "Super Admin" role pills. A plain admin
      registering someone only sees Psychologist/Clinician +
      Psychometrician, and gets "Only a Super Admin can create
      Administrator accounts." / "Only a Super Admin can create
      another Super Admin." if attempted.
    * ROLE EDITING: the same gate applies to the Primary-role
      dropdown and Additional-Roles checkboxes in an employee's
      ASSIGNED ROLES panel.
    * LIST VISIBILITY: super-admin accounts are completely hidden
      from plain admins (filtered out of the table).
    * MANAGE RIGHTS: "Change Password", "Delete Account",
      "Edit Profile" and "Edit Roles" appear on a row only when
      (you are super admin) OR (the row is not an admin). A plain
      admin therefore cannot touch any administrator account at all.
  Every other page treats admin and super_admin identically once the
  branch scope is accounted for.

  9. NOTIFICATIONS AND ANNOUNCEMENTS (HOW EACH ROLE IS INFORMED)
================================================================================
  - Bell (header): per-recipient notifications for every role; polling
    ~60s; click-through deep links (assessment/activity/progress/
    approvals/IEP/attendance pages, often with the exact student and
    form preselected); "Mark all as read"; sidebar count badges.
  - Psychometrician submits work (assessment, daily activity, monthly
    report, IEP, journal-permission change) → treating psychologist
    (or all psychologists) notified "submitted for review ... Please
    review", plus audit entry.
  - Psychologist approves/returns → psychometrician notified; client
    family notified of relevant completions; admins notified of
    activation-type requests.
  - Attendance: psychometrician creates/updates/deletes a monthly
    record → ALL admins/super-admins in the clinic get "Attendance
    record created/updated/deleted ... for {Month}" linking to
    /admin/attendance (badge on the Attendance nav item).
  - Admin publishes announcement → recipients per audience/target get
    "announcement" notifications (+ optional email); admins themselves
    do NOT receive announcement bells — they manage the PUBLISHED list
    directly.
  - Guardian submits an online admission application → admins of that
    branch (and Super Admins) get a "new application" bell
    notification; admins watching the Applications page also get a
    live toast. Clicking the notification jumps to the exact row
    (?application=<id> deep link, Section 7.3). Importing or rejecting
    retires that application's bell items.
  - Branch and role switches never send notifications — they only
    re-scope what YOU see (Sections 3.1–3.2).
  - Appointment booking notifies the family (+ optional email); journal
    access changes notify the caregiver (+ email); compliance completion
    notifies the assigned psychologist/psychometrician ("New student in
    your directory").
  - Approval workflows refresh badges immediately after each decision.

  11. TROUBLESHOOTING AND FAQ
================================================================================
  Q: I cannot log in with my Employee ID.
  A: Type the ID exactly as shown on your profile/slip (for example
     CMPS-EMP-2026-004). Login accepts any letter case. If it still
     fails with "Invalid Account Number or ID", the stored ID may not
     match — ask an admin to confirm your Employee ID in Employee
     Management, or sign in with your account email instead.

  Q: The password-reset code never arrives.
  A: (1) Use the EXACT registered email — the code screen appears even
     for unknown addresses (security), but no email is sent then.
     (2) Check spam. (3) Codes expire in 10 minutes; "Resend Code"
     issues a new one and invalidates the old. (4) Confirm with the
     clinic which email is on your account.

  Q: A psychometrician cannot see a student.
  A: They only see assigned students. An admin must set the student’s
     "Assigned Psychometrician" in Student Management. Also, assessment
     tools stay disabled until admission is complete AND the SPED
     consent (FO-02) is approved (tooltip explains this).

  Q: Daily Journal is locked for a client.
  A: The assigned psychometrician must enable journal access in the
     staff Student Journal page ("Enable Access"). The home card then
     changes from Locked.

  Q: A submitted document cannot be edited.
  A: By design: submitted/approved forms, waivers, and reports become
     read-only. Clinicians must Return/Revalidate it first; clients see
     a "Returned for Revision" banner with the clinic note.

  Q: "Requirements Pending" instead of a form (staff).
  A: That student lacks complete admission or an approved FO-02
     consent. Complete them in Compliance / Waivers first.

  Q: Sidebar item shows no data / "No ... found."
  A: Every directory has search + status filters — clear them first.
     Tables paginate (20/page; announcements published list 3/page).

  Q: Session expired / "Please sign in again".
  A: Your token expired or is missing. Sign in again; form drafts are
     kept where autosave exists (e.g. Daily Activity Report).

  Q: A staff member's lists are empty but colleagues see data.
  A: Two usual causes: (1) WRONG ACTING ROLE — the backend filters by
     the role you are acting as. Open the sidebar profile card and use
     "Switch Role" to pick the matching role (Section 3.2). Note the
     URL always wins (e.g. /admin/* acts as admin), so a notification
     link opened under the wrong role shows an empty directory until
     you switch. (2) WRONG ACTING BRANCH — check the header branch
     switcher (Section 3.1) and pick the branch holding the records.

  Q: There is no branch switcher / no "Switch Role" button in my header.
  A: By design both appear only when there is something to switch
     between. The branch switcher shows only for staff with 2+
     branches (and always for Super Admins); "Switch Role" shows only
     for accounts holding 2+ roles. If you expect access you do not
     have, ask an admin (branch assignment) or a Super Admin (extra
     role) to grant it.

  Q: The build or a page shows an error.
  A: Reload first. If an admin page error persists, note the exact
     message and the URL (including ?patientId/?reportId deep links)
     and report it to the clinic IT/admin.
